Tortoise Capital → Owl Group Trading: keeping old bookmarks working

tortoisecapital.net is still registered and still hosted at Bluehost, but its WordPress install crashes on every page (HTTP 500). The plan: freeze the old site as a static archive on an owlgrouptrading.com subdomain, then make tortoisecapital.net answer every request with a permanent redirect (301) to the same path on that subdomain. A bookmark to any old page lands on that page.

The two options

B · Same page on the archive (recommended)

  • /ken-long/ goes to <sub>/ken-long/ and shows the same content.
  • Search engines carry the old pages' rankings over to the archive pages.
  • Needs a one-time export of the old site into static pages, plus a host for them (for example Cloudflare Pages, where owlgrouptrading.com's DNS already lives).

A · Everything to one landing page

  • Every old URL lands on one welcome page.
  • It's live in minutes and needs no export.
  • The visitor never sees the page they bookmarked, and search engines treat the old pages as gone.

How it is built

  1. Export. Get the old site's files and database through Bluehost cPanel, which still works. Render every page to static HTML at its original path, with a banner pointing to Owl Group Trading. Shop, cart, register and login pages become read-only notices.
  2. Host. Publish the archive at the subdomain. Add one DNS record in the owlgrouptrading.com Cloudflare zone.
  3. Redirect. In tortoisecapital.net's public_html/.htaccess at Bluehost, put the rules below above WordPress's own block. Apache applies them before WordPress runs, so the crash doesn't affect them. Start with a 302, check it, then switch to 301, because browsers cache 301s.
  4. Keep mail. MX for tortoisecapital.net points at Bluehost (mail.tortoisecapital.net). This plan doesn't touch DNS, so email keeps working.
  5. Verify. Request every old URL in the table above and check that it ends on a 200 at the proposed target.
